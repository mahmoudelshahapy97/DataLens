# Pinned runtime dependencies for the backend.
#
# GENERATED FROM requirements.in -- edit that, then regenerate:
#
#   docker run --rm -v "$PWD/backend:/w" -w /w python:3.12-slim sh -c \
#     "pip install -q pip-tools && pip-compile --strip-extras \
#        --output-file=requirements.txt requirements.in"
#
# CI runs `make lock-check`, which regenerates into a temporary file and fails if it
# differs from this one -- so a dependency cannot change without the change appearing
# in a diff.
#
# ---------------------------------------------------------------------------
# Two pins are deliberately behind the newest release, and both are load-bearing:
#
#   pandas 2.x  -- pandas 3 makes copy-on-write the default and changes several
#                  indexing and dtype behaviours. Every SQL result in this system is
#                  a DataFrame; adopting that major belongs in its own change with
#                  its own test run, not in a routine dependency bump.
#   openai 1.x  -- the integration in backend/vanna/integrations/openai targets the 1.x
#                  client surface. 2.x and 3.x reorganise it.
#
# Everything else tracks current. Upper bounds exist where a library has a history of
# breaking minors, and nowhere else -- a bound nobody can justify is a bound somebody
# will silently raise.
# ---------------------------------------------------------------------------
